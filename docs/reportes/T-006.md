### Cómo probar contra la nube (paso a paso)
1. En Neon: crear proyecto/base; Connect → desactivar "Connection pooling" y copiar la cadena **directa**; anteponer `postgresql+psycopg://`.
2. En Cloudflare R2: crear un bucket **privado**; crear un API token con Object Read & Write sobre ese bucket; anotar ID de cuenta, Access Key ID y Secret.
3. PowerShell: `Copy-Item .env.nube.example .env` y reemplazar todos los marcadores (guardar una copia con valores reales como `.env.nube`, ignorado por git).
4. `docker compose up --build`. En los logs, `alembic upgrade head` debe aplicarse sobre Neon (el contenedor `db` arranca pero no se usa).
5. Abrir `http://localhost`, crear un análisis con una foto JPG/PNG y verificar que la imagen se vea al abrirlo.
6. En el panel de R2 → bucket → Objects: debe existir `imagenes/<uuid>.jpg|png`. En Neon (SQL Editor): `select imagen_ruta from analisis;` debe devolver esa misma clave.
7. Eliminar el análisis desde la app. Refrescar el bucket: el objeto debe desaparecer, y la fila, también.
8. Para volver a local: restaurar `.env` desde `.env.example`.

## 4. Problemas encontrados y cómo se resolvieron
| Problema | Causa | Solución |
|---|---|---|
| Un error del validador podía imprimir secretos | Pydantic incluye `input_value` en los errores de validadores de modelo | `hide_input_in_errors=True` y una prueba que verifica que no aparecen |
| `docker compose` exige `POSTGRES_*` aunque no se use la BD local | `db` y su healthcheck interpolan esas variables, y `backend` depende de `db` | `.env.nube.example` incluye `POSTGRES_*` con valores sin uso |

## 5. Decisiones tomadas
- `guardar` con extensión distinta de `jpg`/`png` lanza `ValueError` (el caso de uso solo pasa esas dos).
- Clave válida: `imagenes/<uuid en formato 8-4-4-4-12 hex minúscula>.(jpg|png)`; se valida en `leer` y `eliminar`.
- `leer` traduce `NoSuchKey`/`404`/`NotFound` a `FileNotFoundError`; otros `ClientError` (permisos, red) se propagan.
- Firma `s3v4` explícita en el cliente (requerida por R2).
- `FileNotFoundError` hoy: ningún manejador de la API lo captura (`obtener_imagen` lo deja subir), por lo que equivale a un 500 tanto en local como en S3. Se mantuvo igual, como pedía el enunciado.
