# T-004 — Calibración de escala y región excluida

**Objetivo:** que el operador pueda calibrar la escala y marcar la región del objeto de escala a través de la API, con las reglas del dominio aplicadas. Cubre HU-02 y HU-03 en el backend.

**Lee antes:** CLAUDE.md, docs/dominio.md, docs/api.md (sección "Calibración y exclusión").

## Alcance

### 1. Dominio (TDD)
- Nueva regla: los puntos de la calibración y todos los vértices de la región excluida deben estar dentro de la imagen (0 ≤ x ≤ ancho_px, 0 ≤ y ≤ alto_px). Si no: `CalibracionNoValida` y `PoligonoNoValido` respectivamente. La validación vive en `Analisis.calibrar` y `Analisis.excluir_region`, que conocen la imagen.
- Actualiza docs/dominio.md con la regla.

### 2. Casos de uso (`app/aplicacion/casos_de_uso/`)
- `CalibrarEscala(id, inicio, fin, longitud_mm) -> Analisis`
- `ExcluirRegion(id, puntos) -> Analisis`
- `QuitarRegionExcluida(id) -> None` (idempotente: si no hay región, no falla)
Cada uno obtiene el agregado, invoca el método del dominio y lo guarda. Id inexistente → `AnalisisNoEncontrado`.

### 3. API (`router_analisis.py` o un router nuevo `router_calibracion.py`)
Rutas exactamente como en docs/api.md:
- `PUT /api/analisis/{id}/calibracion` → `200 {"factor_mm_por_px": float, "estado": str}`
- `PUT /api/analisis/{id}/region-excluida` → `200` AnalisisDetalle
- `DELETE /api/analisis/{id}/region-excluida` → `204`
Esquemas Pydantic con coordenadas `float` finitas (rechaza NaN/infinito → 422). `AnalisisDetalle` ya debe mostrar `calibracion` (con `factor_mm_por_px`) y `region_excluida` cuando existen.

## Pruebas
- Dominio: puntos fuera de la imagen (calibración y región), justo en el borde (válidos).
- Casos de uso con los fakes existentes, incluido id inexistente.
- API: calibrar con inicio (0,0), fin (300,400) y 250 mm sobre una imagen de 1600×1200 → factor 0.5 y estado CALIBRADO; longitud 0 → 422; punto (2000, 0) → 422; región válida → aparece en el detalle; quitar región → 204 y desaparece; quitar dos veces → 204; id inexistente → 404.
- Repositorio (con TEST_DATABASE_URL): calibrar y excluir región, guardar, recuperar y comparar.

## Criterios de aceptación
1. `pytest` en verde (incluidas las de PostgreSQL al menos una vez).
2. Cobertura de dominio y aplicación ≥ 90 %.
3. `ruff check .` sin errores; prueba de arquitectura en verde.
4. Con `docker compose up --build`, por nginx y con curl: crear un análisis con una foto real, calibrarlo, marcar la región, consultar el detalle (muestra ambas), quitar la región y eliminar el análisis. Pega las salidas resumidas.
5. Reporte con la plantilla y commits sugeridos.
