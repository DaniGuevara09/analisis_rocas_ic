# T-001 — Estructura del repositorio, Docker Compose y esqueletos

**Objetivo:** dejar el repositorio listo para que las siguientes tareas solo agreguen funcionalidad: estructura de carpetas según `docs/arquitectura.md`, backend y frontend mínimos que se comunican, y todo levantando con `docker compose up`.

**Lee antes:** `CLAUDE.md`, `docs/arquitectura.md`.

## Alcance

### Raíz
- `.gitignore` (Python, Node, `.env`, `backend/modelos/*.pt`, cachés, builds).
- `.gitattributes` que fuerce `eol=lf` en `*.sh`, `*.py`, `*.ts`, `*.tsx`, `Dockerfile` (el equipo usa Windows).
- `.env.example` con `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `DATABASE_URL`, `RUTA_IMAGENES`, `RUTA_MODELO`.
- `docker-compose.yml` con los servicios `db` (postgres:16, healthcheck), `backend` y `frontend`, y los volúmenes `pgdata` e `imagenes`. Solo `frontend` expone puerto (80).
- `docker-compose.override.example.yml` que expone 8000 (backend) y 5432 (db) para desarrollo.
- `README.md` con: qué es el proyecto (2 líneas), requisitos (Docker Desktop), cómo levantarlo, cómo correr las pruebas.

### Backend (`backend/`)
- `pyproject.toml` con dependencias: fastapi, uvicorn[standard], sqlalchemy>=2, alembic, psycopg[binary], pydantic-settings, python-multipart, pillow. Desarrollo: pytest, httpx, ruff. **No** agregues ultralytics todavía.
- Estructura completa de carpetas de `docs/arquitectura.md` con `__init__.py`. Los módulos de dominio, puertos y adaptadores quedan vacíos o con un docstring que explique su responsabilidad; **no** implementes lógica de negocio.
- `app/config.py` con pydantic-settings leyendo las variables de `.env.example`.
- `app/main.py` con la app FastAPI montada en `/api`, documentación en `/api/docs` y la ruta `GET /api/salud` → `{"estado": "ok"}`.
- Alembic inicializado (`alembic.ini`, `alembic/env.py` leyendo `DATABASE_URL`), sin migraciones.
- `Dockerfile` (python:3.12-slim) que ejecute uvicorn.
- Pruebas:
  - `tests/integracion/test_salud.py`: `GET /api/salud` devuelve 200 y `{"estado":"ok"}`.
  - `tests/unit/test_arquitectura.py`: recorre los `.py` de `app/dominio/` y falla si importan `fastapi`, `sqlalchemy`, `pydantic`, `ultralytics`, `alembic`, `os` o `pathlib`, o cualquier módulo de `app.aplicacion` o `app.adaptadores`; y recorre `app/aplicacion/` y falla si importan algo de `app.adaptadores` o frameworks. Esta prueba protege la regla hexagonal en todas las tareas futuras.

### Frontend (`frontend/`)
- Proyecto Vite + React 18 + TypeScript (`strict: true`). Instala `react-konva` y `konva` ahora para fijar versiones, aunque no se usen todavía.
- `src/tema/tokens.css` con variables CSS: colores (fondo `#F4F5F7`, superficie `#FFFFFF`, encabezado `#3E4C59`, acento `#1F3A5F`, texto `#1E2226`, texto secundario `#6B7178`, borde `#D5D9DD`, error `#B00020`), tipografía, tamaños de fuente, espaciados y radios. Importado una sola vez en `main.tsx`.
- Carpetas `api/`, `componentes/`, `editor/`, `pantallas/` (con un `.gitkeep` o un archivo índice).
- `src/api/cliente.ts`: función `obtenerSalud()` que llama a `/api/salud`.
- Una pantalla provisional que muestre el título "Análisis Granulométrico de Roca" y el estado de la API ("API: ok" o "API: sin conexión"), usando solo variables de `tokens.css`.
- `vite.config.ts` con proxy de `/api` a `http://localhost:8000` para desarrollo.
- `Dockerfile` multi-etapa (node para el build, nginx para servir) y `nginx.conf` que sirva el build y redirija `/api/` al servicio `backend:8000`.

## Fuera de alcance
Entidades, cálculos, tablas de base de datos, casos de uso, pantallas reales, autenticación, YOLO.

## Criterios de aceptación
1. `docker compose up --build` levanta los tres servicios sin errores y `http://localhost` muestra "API: ok".
2. `http://localhost/api/docs` muestra la documentación de FastAPI.
3. Dentro de `backend/`: `pytest` pasa (2 pruebas como mínimo) y `ruff check .` no reporta errores.
4. Dentro de `frontend/`: `npm run build` termina sin errores de TypeScript.
5. La prueba de arquitectura falla si se agrega `import fastapi` a un archivo de `app/dominio/` (verifícalo y luego revierte el cambio; documenta la verificación en el reporte).
6. Ningún componente del frontend contiene colores o tamaños literales.
7. Reporte escrito en `docs/reportes/T-001.md` con la plantilla.

## Si no tienes Docker disponible
Verifica los criterios 3, 4, 5 y 6 localmente, documenta en el reporte que el criterio 1 y 2 no se pudieron probar y por qué. No lo marques como cumplido.
